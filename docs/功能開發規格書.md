# 煮意 功能開發規格書

> 本文件隨專案版本控管，為前端、後端與設計驗收的共同依據。完整歷史草稿保留於專案外層 `../docs/`；本檔是團隊應持續更新的專案內規格。

## 1. 第一版範圍

| 模組 | 使用者目標 | 第一版功能 |
| --- | --- | --- |
| 家庭管理 | 記錄家人的飲食需求 | 成員新增、查詢、編輯、刪除、復原提示 |
| 冰箱庫存 | 管理食材與保存期限 | 食材新增、查詢、編輯、刪除、到期日與整理冰箱檢視 |
| 餐食日誌 | 安排每日晚餐 | 月曆檢視、晚餐排程、帶入今日晚餐 |
| 採買清單 | 補足排餐所需食材 | 排餐同步建立、手動新增/刪除、購入勾選 |

第一版暫不含營養分析、通知推播及多人即時協作。

## 2. 使用者、家庭與資料模型

- 第一版僅支援登入使用者管理自己可存取的家庭資料。
- `owner` 可管理家庭名稱、邀請及移除使用者；`member` 可管理家庭成員、庫存、晚餐與採買清單。
- 資料庫使用 PostgreSQL、UUID 與 `timestamptz`；家庭時區預設 `Asia/Taipei`。

```text
users
  └─ households
       ├─ household_users
       ├─ household_members
       │    └─ member_ingredient_preferences ─ ingredients
       ├─ inventory_items ─ ingredients
       ├─ meal_plans ─ recipes
       │                   └─ recipe_ingredients ─ ingredients
       └─ grocery_lists
            └─ grocery_list_items ─ ingredients
```

| 資料表 | 主要欄位 |
| --- | --- |
| `households` | `id`, `name`, `timezone`, `created_by` |
| `household_users` | `household_id`, `user_id`, `role` |
| `household_members` | `id`, `household_id`, `name`, `portion_factor`, `spice_level` |
| `ingredients` | `id`, `name`, `default_unit` |
| `inventory_items` | `id`, `household_id`, `ingredient_id`, `quantity`, `unit`, `storage_location`, `expires_on` |
| `recipes` / `recipe_ingredients` | 食譜與所需食材 |
| `meal_plans` | `household_id`, `meal_date`, `meal_type`, `recipe_id`, `meal_name`, `servings` |
| `grocery_lists` / `grocery_list_items` | 每週採買清單與品項 |

## 3. 共用版面與 RWD（強制）

所有既有與後續頁面都必須以「家庭管理」的桌面比例及 `PageTitle` 為唯一母版；不得在單一頁面自行覆寫頁首頁距、字級或尺寸。

- **≥1920px**：`240px` 左側導覽 / `1440px` 主內容 / `240px` 右側留白；更寬時額外空間平均保留左右。
- **1024–1919px**：維持 `12.5vw / 75vw / 12.5vw` 比例，左側導覽固定於捲動時不移動。
- **768–1023px**：單欄平板版。
- **<768px**：頂部導覽與單欄手機版。
- 桌機頁首內距：`48px 32px 33px`；標題 `29px`、標題與說明間距 `10px`、說明 `13px`、底部 `1px` 分隔線。
- 頁首右側操作須同一垂直基線；冰箱切換按鈕、家庭管理新增成員等只替換內容，不改變頁首母版尺寸。
- 所有彈窗白底、細框、深色遮罩，採左上/右下 `12px`、右上/左下 `0px` 的 `border-radius: 12px 0 12px`。
- 桌機完整表單需一次可見；僅螢幕高度不足或手機版允許內容捲動。桌機新增食材彈窗禁止中段垂直捲動。

## 4. 家庭管理

### 畫面與互動

- 顯示標題、常駐用餐人數與每餐總份量兩張指標卡、成員卡與新增成員卡。
- 成員卡顯示姓名、份量係數、過敏/忌口、飲食需求、辣度偏好與最近更新時間。
- 桌面空狀態以 Figma `1174:20733` 為比例依據；新增成員虛線卡高度 `334.5px`，整張可點擊。
- 新增/編輯成功後立即更新指標與名冊，不重整頁面。
- 刪除前顯示確認；成功 Toast 為 `已刪除成員「{姓名}」`，可於 5 秒內復原。

| 欄位 | 規則 |
| --- | --- |
| 姓名 | 必填、1–20 字、同家庭不可重複 |
| 份量係數 | 必填、0.5–3.0，預設 1.0 |
| 辣度 | `none`、`light`、`mild`、`medium`、`hot`；預設不辣 |
| 過敏/忌口 | 多選且同一食材不得重複 |
| 飲食需求 | 自由文字 |
| 頭貼 | 本機選擇後即時預覽，儲存後顯示於成員卡 |

內建食材標籤點擊僅改變選取底色；自訂食材經輸入後按新增或 Enter 建立，可顯示 `×` 移除。

## 5. 冰箱庫存

### 檢視模式

| 檢視 | 顯示內容 |
| --- | --- |
| 列表 | 摘要卡、分類篩選、搜尋、食材表格與可做料理區；空庫存提供「立刻登記第一批食材」 |
| 整理冰箱 | 冷凍庫/冷藏室/蔬果抽屜，以及常溫櫃/調味架的食材格 |

- 列表篩選：全部、冷藏、冷凍、蔬果室、常溫/調味；關鍵字搜尋即時套用。
- 距今日 3 天內到期為紅色；4–7 天黃色；其餘棕色；過期顯示「已過期」。
- 整理模式食材卡與空格固定 `98px × 127px`。冷凍庫、蔬果抽屜每列五格；冷藏室、常溫櫃、調味架為兩列各五格。
- 同一櫃位超過既定格數時，僅該櫃位橫向捲動，不縮小、不換行。
- 已登記食材卡顯示 `80px × 80px` 的 `img/reffood` 圖片、名稱、右上數量與底部鮮度條。
- 冰箱初始保持空狀態；新增食材後依名稱比對 `img/reffood`。沒有對應圖片時保留文字預設卡，不阻擋新增。
- 名稱含油、醬、鹽、醋、粉、香料、辣或胡椒者在整理模式歸入調味架，其餘常溫食材歸入常溫櫃。
- 少於兩項食材時「現有庫存可做料理」顯示空狀態；達兩項顯示三張推薦料理卡。

### 新增與編輯食材彈窗

「Desktop - 冰箱／新增食材」以 Figma `1174:25434`（`ref/addnewfood/mc`）為唯一母元件：外框 `620px × 587px`，標題列 `77px`、表單區 `438px`、固定操作列 `70px`。

- 標題 24px、說明 12px；欄位高 `44px`、圓角 `12px`。
- 表單依序：食材名稱、快捷、數量/單位、四個溫區卡、自訂有效日期。
- 「新增食材」按鈕必須與「新增成員」相同：高 `39px`、水平內距 `10px`、字級 `13px`。
- 數量控制與單位欄維持 **1:1 等寬**，間距 `12px`；減號/加號各 `36px`。
- 單位使用 Figma `ref/unit/click` 自訂選單，非原生 `<select>`；未選取為「請選擇」與 `#A39D9A`，選單依常用/重量/容量分組並於選取後立即收合。
- 日期欄只顯示一個 Figma 日曆圖示；隱藏瀏覽器原生日曆指示器，仍保留可點擊開啟日期選擇。
- 快捷：雞蛋、牛番茄、嫩豆腐、梅花豬肉片；點擊只帶入名稱，仍可修改。

#### 溫區卡顏色與狀態（強制）

| 狀態 | 邊框/分隔線 | 圓點 | 文字 | 圖示 |
| --- | --- | --- | --- | --- |
| 未選取 | `1px #F2EFEC` | `#E9E1D9` | `#716C6C` | `#B0BFD2` |
| 選取 | `2px #856F5B` | `#856F5B` | `#5A4A3B` | `#5E7391` |

選取時維持白底，卡片尺寸不可跳動。欄位標籤 `#5A4A3B`、提示 `#A39D9A`、溫區文字 `#716C6C`，快捷底色與未選圓點 `#E9E1D9`。

| 欄位 | 規則 |
| --- | --- |
| 食材名稱 | 必填、1–50 字 |
| 數量 | 必填、0.5–500、支援 0.5 間距 |
| 單位 | 份、顆、片、包、盒、把、瓶、罐 |
| 保存位置 | 冷藏（+3 天）、冷凍（+30 天）、蔬果室（+5 天）、常溫/調味（+90 天） |
| 有效日期 | 選溫區後以當日加建議天數預填，可覆寫為 `YYYY-MM-DD` |

使用 Pinia 與 `localStorage` 的 `zhuyi:fridge-ingredients` 儲存 `id`、`name`、`amount`、`unit`、`zone`、`expiry`、建立/更新/軟刪除時間。新增成功 Toast：`已將「{食材} {數量} {單位}」加入{保存分區}，預估 {天數} 天內食用完畢`。

## 6. 餐食日誌與採買整合

餐食日誌提供月曆/列表、建立/編輯/刪除晚餐及帶入今日晚餐；排餐異動同步採買清單。

| 欄位 | 規則 |
| --- | --- |
| 日期 | 必填；可補登過去日期 |
| 食譜或簡易餐食 | 二擇一，簡易餐食 1–80 字 |
| 份數 | 必填，預設有效家庭成員份量總和 |
| 備註 | 最多 200 字 |

```text
建立或修改晚餐
  → 取得食譜與所需食材
  → 依份數換算需求量
  → 彙總同一購買週期的未完成晚餐
  → 扣除有效冰箱庫存
  → 建立或更新尚未購入的採買項目
```

採買規則：相同食材、相同單位才可合併及扣抵；採買數量為 `max(0, 晚餐總需求量 - 可用庫存量)`；手動項目 (`source_type = manual`) 不得被同步覆蓋或刪除；系統排餐項目為 `planned_dinner`。過敏衝突禁止儲存，忌口顯示警告後可確認繼續。

## 7. API 初稿

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| `GET/POST` | `/api/households/:id/members` | 取得/新增成員 |
| `PATCH/DELETE` | `/api/members/:id` | 編輯/軟刪除成員 |
| `POST` | `/api/members/:id/restore` | 復原成員 |
| `GET/POST` | `/api/households/:id/inventory` | 取得/新增庫存 |
| `PATCH/DELETE` | `/api/inventory/:id` | 編輯/軟刪除庫存 |
| `GET/POST` | `/api/households/:id/meal-plans` | 取得/建立排餐 |
| `PATCH/DELETE` | `/api/meal-plans/:id` | 更新/刪除排餐 |
| `GET` | `/api/households/:id/grocery-list` | 取得採買清單 |
| `PATCH` | `/api/grocery-list-items/:id` | 更新數量或購入狀態 |
| `POST` | `/api/grocery-list-items/:id/add-to-inventory` | 由採買項目預填建立庫存 |

所有 API 使用 JSON；未登入 `401`、無權限 `403`、找不到資源 `404`、驗證失敗 `422`，格式為 `{ "message": "...", "errors": { "欄位": ["原因"] } }`。

## 8. 驗收與開發順序

1. Vue 路由、共用版面與家庭管理。
2. 家庭 CRUD、提示與本機儲存。
3. 冰箱 CRUD、到期提醒、列表/整理模式及 `reffood` 圖片。
4. 食譜、餐食日誌與採買同步。
5. API 串接、測試、錯誤處理與行動版驗收。

所有列表均需處理空狀態、讀取中與錯誤狀態；主要操作提供鍵盤可達性與明確按鈕名稱。正式串 API 時，保留目前資料欄位與驗證規則。
